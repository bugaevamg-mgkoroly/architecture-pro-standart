Обоснование ключевых требований
Централизованное управление ставками

Почему: Сейчас ставки хранятся в XLS‑файлах, что создаёт риски ошибок и несогласованности.

Решение: Внедрение единого источника данных (например, в АБС) с API для сайта и интернет‑банка.

Горизонтальное масштабирование

Почему: Рост числа онлайн‑заявок может перегрузить текущие системы.

Решение: Распределение нагрузки между серверами и ЦОД, использование Kafka для очередей.

Шифрование данных

Почему: Передача персональных данных (Ф. И. О., паспортные данные) требует защиты.

Решение: TLS для трафика, шифрование хранилищ данных.

Интеграция АБС и Кредитного конвейера

Почему: Менеджеры должны видеть все заявки (с сайта, интернет‑банка, отделений) в единой системе.

Решение: API‑интеграции с передачей статусов заявок между системами.

Мониторинг и логирование

Почему: Для быстрого выявления и устранения сбоев.

Решение: Внедрение инструментов мониторинга (например, Prometheus + Grafana) и централизованного логирования (ELK Stack).

Микросервисная архитектура

Почему: Текущий монолит интернет‑банка ограничивает гибкость.

Решение: Постепенный переход на микросервисы для отдельных функций (например, открытие депозитов).

Тестирование нагрузки на АБС

Почему: АБС уже перегружена; онлайн‑заявки могут вызвать сбои.

Решение: Нагрузочное тестирование перед запуском MVP, оптимизация запросов.

Примечания
Приоритеты: «Высокий» — критично для MVP; «Средний» — важно для долгосрочной устойчивости.

Технологии: Учитываются существующие стеки банка (ASP.NET, Oracle, MS SQL, Java Spring Boot) и перспективы (Kafka, микросервисы).

Безопасность: Все требования к защите данных соответствуют ФЗ‑152 и банковским стандартам.
