### <a name="_qmphm5d6rvi3"></a>**Решение**

Диаграмма контекста (C4 Level 1)[]

**Компоненты:**

Клиент — физическое лицо, подающее заявку.

Сайт/интернет‑банк — точки входа для заявки.

АБС — ядро процесса (хранение данных, проведение операций).

Система скоринга — автоматическая проверка кредитоспособности.

БКИ — внешняя система для проверки кредитной истории.

SMS‑шлюз — уведомления клиенту.

Сервис ЭП — электронное подписание.

Диаграмма контейнеров (C4 Level 2)[]

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

1. Полная интеграция с бюро кредитных историй (БКИ) через прямое API (без промежуточного сервиса скоринга)

Плюс:

Сокращение времени обработки заявки за счёт отсутствия промежуточного звена.

Повышение точности данных (прямая выгрузка из БКИ).

Минус:

Высокие требования к безопасности API БКИ.

Зависимость от доступности внешнего сервиса.

Необходимость доработки АБС под формат БКИ.

2. Децентрализованная обработка заявок (P2P‑модель между филиалами банка)

Плюс:

Снижение нагрузки на центральное ядро системы.

Возможность локальной обработки в регионах.

Минус:

Риск несогласованности решений между филиалами.

Усложнение аудита и мониторинга.

Дополнительные затраты на синхронизацию данных.

3. Использование облачного сервиса скоринга (SaaS)

Плюс:

Отсутствие затрат на разработку собственного сервиса скоринга.

Автоматическое обновление ML‑моделей.

Минус:
Передача персональных данных во внешний облачный сервис (риски безопасности).

Ежемесячные платежи за использование SaaS.

Ограниченная кастомизация под специфику банка.

4. Ручная обработка всех заявок без автоматизации

Плюс:

Максимальная гибкость при принятии решений (учёт нестандартных случаев).

Отсутствие затрат на IT‑инфраструктуру.

Минус:

Время обработки заявки — от 1 дня.

Высокий риск ошибок из‑за человеческого фактора.

Невозможность масштабирования (1 специалист — 10–15 заявок в день).

**Недостатки, ограничения, риски**

**Недостатки выбранного решения**

1. Зависимость от работоспособности API БКИ

Сбой в БКИ → остановка обработки заявок.

2. Ограниченная кастомизация скоринга

ML‑модели требуют регулярного переобучения под изменения рынка.

3. Сложность интеграции ЭП

Несовместимость с некоторыми устройствами клиентов (старыми смартфонами, ПК).

4. Высокие требования к инфраструктуре

Необходимость резервирования RabbitMQ и БД кредитов.

5. Задержка в уведомлениях

SMS‑шлюз может не доставить сообщение в течение 5–10 мин.

**Ограничения**

**Технические:**

Поддержка только ГОСТ‑совместимой ЭП (исключает иностранные аналоги).

Ограничение на размер заявки: до 5 млн руб. (из‑за правил БКИ).

**Правовые:**

Запрет на обработку заявок без согласия на проверку кредитной истории.

Обязательное хранение данных в РФ (требования ФЗ‑152).

**Операционные:**

Обработка заявок только в рабочие дни (9:00–18:00 МСК).

Лимит 1 000 заявок/час (пропускная способность RabbitMQ).

**Функциональные:**

Отсутствие поддержки юрлиц (только физлица).

Нет возможности изменить условия кредита после отправки заявки.

**Риски**

**Безопасность:**

Утечка персональных данных через API БКИ или SMS‑шлюз.

Компрометация ключей ЭП (подделка подписей).

**Технологические:**

Перегрузка RabbitMQ при пиковых нагрузках → потеря заявок.

Сбой АБС → остановка выдачи кредитов.

**Бизнес‑риски:**

Ложные отказы из‑за ошибок скоринга → потеря клиентов.

Задержки в переводе средств → претензии со стороны заёмщиков.

**Регуляторные:**

Нарушение требований ЦБ РФ по хранению кредитных историй.

Штрафы за несоблюдение сроков уведомления клиентов.

**Репутационные:**

Некорректные уведомления (например, «Кредит одобрен» при фактическом отказе).

Длительные простои системы → негатив в соцсетях.

**Операционные:**

Ошибки при ручном вмешательстве (корректировка скоринга специалистом).

Потеря данных при резервном копировании (если не настроен мониторинг).

**Внешние:**

Изменение законодательства о кредитовании (требует срочной доработки системы).

Санкции против поставщиков облачных сервисов (если используется SaaS).
