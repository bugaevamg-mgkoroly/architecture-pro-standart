ADR: Заявка на кредит онлайн (MVP)
1. Контекст

Банк «Стандарт» планирует цифровизировать процесс подачи заявок на кредиты. Цель — позволить клиентам оформлять заявки через сайт и интернет‑банк с получением предварительного решения в течение 1 дня.

Ключевые ограничения:

система кредитного скоринга испытывает высокую нагрузку в рабочие часы;

АБС поддерживает только вертикальное масштабирование;

интернет‑банк реализован как монолит на ASP.NET MVC 4.5;

требуется соблюдение ФЗ‑152 (защита персональных данных);

доступность сервисов — 99,9% времени (24/7);

партнёрский кол‑центр использует внешнюю систему без API‑интеграции.

2. Требования

Функциональные:

клиент видит список кредитных продуктов на сайте и в интернет‑банке;

клиент подаёт заявку на кредит, указывая Ф. И. О., телефон, паспортные данные;

система проводит скоринг на основе данных из Бюро кредитных историй (БКИ);

клиент получает предварительное решение по кредиту в течение 1 дня;

менеджер в отделении продолжает работу с существующей заявкой (с сайта/интернет‑банка);

клиент получает СМС‑уведомления о статусе заявки;

сотрудники кол‑центра видят статус заявки в своей системе.

Нефункциональные:

время отклика интерфейса — ≤ 200 мс;

обработка скоринга — ≤ 30 сек;

горизонтальное масштабирование системы скоринга и кредитного конвейера;

шифрование персональных данных и трафика;

аудит всех действий с заявками;

поддержка до 500 одновременных заявок.

Архитектурно значимые требования:

минимизация нагрузки на систему кредитного скоринга;

изоляция процессов скоринга от основных операций;

единая система учёта заявок (интеграция сайта, интернет‑банка, АБС, кредитного конвейера);

возможность постепенного внедрения (MVP → финальное решение).

3. Рассматриваемые альтернативы

Прямая интеграция сайта/интернет‑банка с системой скоринга

Плюс: простота реализации.

Минус: риск перегрузки системы скоринга, нарушение требований производительности.

Введение промежуточного сервиса обработки заявок

Плюс: буферизация нагрузки, возможность кэширования предодобренных предложений.

Минус: дополнительные затраты на разработку.

Использование очередей сообщений (Kafka)

Плюс: отказоустойчивость, асинхронная обработка.

Минус: несовместимость с текущей платформой интернет‑банка.

Выбранное решение: вариант 2 (промежуточный сервис) как оптимальный баланс между рисками и требованиями MVP.

4. Решение

Диаграмма контекста (C4 Model)
Пользователь (Клиент) → [Сайт банка]  
Пользователь (Клиент) → [Интернет-банк]  
Менеджер фронт-офиса → [АБС]  
Оператор кол-центра → [Система кол-центра]  

[Сайт банка] → [Сервис обработки кредитных заявок]  
[Интернет-банк] → [Сервис обработки кредитных заявок]  
[Сервис обработки кредитных заявок] → [Система кредитного скоринга]  
[Сервис обработки кредитных заявок] → [Кредитный конвейер]  
[Сервис обработки кредитных заявок] → [СМС-шлюз]  
[Система кол-центра] ←→ [Сервис обработки кредитных заявок]  
[АБС] ←→ [Кредитный конвейер]  
[Бюро кредитных историй] → [Система кредитного скоринга]  
Компоненты:

Сайт банка / Интернет‑банк — отображение кредитных продуктов, сбор данных заявки.

Сервис обработки кредитных заявок — оркестрация процессов, валидация данных, маршрутизация.

Система кредитного скоринга — расчёт рейтинга клиента на основе данных БКИ.

Кредитный конвейер — обработка заявок, интеграция с АБС.

СМС‑шлюз — отправка уведомлений о статусе заявки.

Система кол‑центра — просмотр статуса заявок, консультации клиентов.

АБС — утверждение кредита, учёт операций.

Бюро кредитных историй — источник данных для скоринга.

Диаграмма компонентов (детализация сервиса обработки кредитных заявок)
Сервис обработки кредитных заявок:

API для сайта и интернет‑банка (REST);

модуль валидации данных заявки;

модуль маршрутизации в систему скоринга или кредитный конвейер;

БД PostgreSQL (заявки, статусы, логгирование);

модуль формирования СМС‑уведомлений;

кэш предодобренных предложений (для ускорения обработки повторных заявок).

5. Последствия

Плюсы:

снижение нагрузки на систему скоринга за счёт кэширования;

единая точка учёта заявок для всех каналов;

соответствие требованиям безопасности и доступности;

возможность горизонтального масштабирования сервиса обработки заявок.

Минусы:

дополнительная сложность из‑за нового сервиса;

необходимость синхронизации статусов между системами (АБС, кредитный конвейер, кол‑центр).

Следующие шаги:

Разработка «Сервиса обработки кредитных заявок».

Интеграция с системой кредитного скоринга.

Настройка взаимодействия с кредитным конвейером и АБС.

Тестирование нагрузки на систему скоринга.

Внедрение модуля СМС‑уведомлений.

6. Ограничения решения

Текущая платформа интернет‑банка (ASP.NET MVC 4.5) ограничивает внедрение Kafka.

Вертикальное масштабирование АБС может стать узким местом при росте заявок.

Система скоринга не поддерживает предрасчёт скорингов для всех клиентов — требуется оптимизация алгоритмов.

Партнёрский кол‑центр не имеет API‑доступа к статусам заявок (требуется ручная выгрузка данных).
