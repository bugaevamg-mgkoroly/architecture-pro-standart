ADR: Открытие депозитов онлайн (MVP)
1. Контекст

Банк «Стандарт» стремится увеличить клиентскую базу за счёт цифровизации депозитных продуктов. Текущие процессы требуют участия сотрудников бэк‑офиса и посещения отделения. Цель MVP — позволить клиентам подавать заявки на депозиты через сайт и интернет‑банк с минимальной ручной обработкой.

Ключевые ограничения:

АБС перегружена и поддерживает только вертикальное масштабирование;

интернет‑банк реализован как монолит на ASP.NET MVC 4.5;

ставки по депозитам хранятся в XLS‑файлах;

требуется защита персональных данных (ФЗ‑152);

доступность сервисов — 99,9% времени.

2. Требования

Функциональные:

клиент видит список депозитов с ставками на сайте и в интернет‑банке;

подача заявки на депозит через сайт (Ф. И. О., телефон) или интернет‑банк (счёт, сумма);

подтверждение операции через СМС‑код;

обработка заявки менеджером бэк‑офиса в АБС (MVP);

уведомления клиента через СМС о статусе заявки.

Нефункциональные:

время отклика интерфейса — ≤ 200 мс;

обработка СМС — ≤ 5 сек;

горизонтальное масштабирование интернет‑банка и кол‑центра;

шифрование трафика и данных;

аудит действий пользователей.

3. Рассматриваемые альтернативы

Прямая интеграция интернет‑банка с АБС

Плюс: простота реализации.

Минус: риск перегрузки АБС, нарушение требований доступности.

Введение промежуточного сервиса оркестрации

Плюс: снижение нагрузки на АБС, гибкость маршрутизации заявок.

Минус: дополнительные затраты на разработку.

Использование Kafka для очередей

Плюс: отказоустойчивость, буферизация нагрузки.

Минус: несовместимость с текущей платформой интернет‑банка.

Выбранное решение: вариант 2 (промежуточный сервис) как баланс между рисками и требованиями MVP.

4. Решение

Диаграмма контекста (C4 Model)
Пользователь (Клиент) → [Сайт банка]  
Пользователь (Клиент) → [Интернет-банк]  
Менеджер бэк-офиса → [АБС]  


[Сайт банка] → [Сервис подачи заявок]  
[Интернет-банк] → [Сервис подачи заявок]  
[Сервис подачи заявок] → [АБС]  
[Сервис подачи заявок] → [СМС-шлюз]  
[Сервис подачи заявок] → [Система хранения ставок]  
[Кол-центр] ←→ [Сервис подачи заявок]  
Компоненты:

Сайт банка — отображение депозитов, сбор базовых данных заявки.

Интернет-банк — персонализированные ставки, подача полной заявки.

Сервис подачи заявок — оркестрация процессов, валидация данных, маршрутизация в АБС.

АБС — утверждение ставки, открытие депозита, хранение данных.

СМС-шлюз — отправка уведомлений.

Система хранения ставок — централизованное управление ставками (замена XLS).

Кол-центр — обработка заявок с сайта, согласование условий.

Диаграмма контейнеров (детализация интернет-банка и АБС)
Интернет-банк:

Веб-сервер (ASP.NET MVC 4.5);

БД MS SQL (пользовательские данные, сессии);

Модуль СМС-подтверждения (интеграция с шлюзом);

API для взаимодействия с «Сервисом подачи заявок».

АБС:

Десктопный клиент (Delphi);

БД Oracle (счета, транзакции, ставки);

PL/SQL-процедуры для обработки заявок;

API для интеграции с «Сервисом подачи заявок».

Сервис подачи заявок:

Микросервис на Java Spring Boot;

БД PostgreSQL (заявки, логгирование);

Kafka (опционально, для буферизации в перспективе).

5. Последствия

Плюсы:

снижение нагрузки на АБС за счёт промежуточного сервиса;

соответствие требованиям безопасности (шифрование, аудит);

возможность горизонтального масштабирования интернет‑банка.

Минусы:

дополнительная сложность из‑за нового сервиса;

необходимость синхронизации ставок между XLS и новой системой хранения.

Следующие шаги:

Разработка «Сервиса подачи заявок».

Миграция ставок из XLS в централизованную систему.

Интеграция сервиса с АБС и интернет‑банком.

Тестирование нагрузки на АБС.
