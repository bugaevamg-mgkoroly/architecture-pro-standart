### <a name="_qmphm5d6rvi3"></a>**Решение**
Приведите диаграммы контекста и контейнеров в модели C4. Опишите там основные компоненты и интеграции всех элементов решения. 

Также опишите, какой логикой вы руководствовались в ходе принятия решений и выбора технологий. Не забывайте, что необходимо учесть все функциональные и нефункциональные требования.

Основные компоненты и интеграции:

Источники данных:

АБС (Oracle, PL/SQL) — хранит актуальные ставки, историю изменений.

Промежуточные сервисы:

Сервис синхронизации ставок — опрашивает АБС каждые 15 мин, обновляет ставки в БД кол‑центра.

Сервис экспорта ставок — формирует файл (CSV/XLSX), выкладывает на SFTP партнёра.

БД кол‑центра (PostgreSQL) — хранит ставки для быстрого доступа сотрудников.

Приёмники данных:

Система кол‑центра банка (React.js + Spring Boot) — отображает ставки в интерфейсе оператора.

SFTP‑сервер партнёра — принимает файл со ставками.

Интеграции:

АБС → Сервис синхронизации ставок → БД кол‑центра → Система кол‑центра банка.

АБС → Сервис экспорта ставок → SFTP‑сервер партнёра.

Администратор АБС → АБС (внесение изменений).

Логика принятия решений:

Синхронизация каждые 15 мин — баланс между актуальностью и нагрузкой на АБС.

Файл на SFTP — единственный доступный способ интеграции с партнёром (нет API).

Формат CSV/XLSX — совместимость с Excel, простота обработки.

SSH‑ключи для SFTP — безопасная аутентификация без паролей.

Журналирование — аудит и отладка процессов выгрузки.

Резервный сервис экспорта — отказоустойчивость при сбоях.



### <a name="_bjrr7veeh80c"></a>**Альтернативы**

1. Передача ставок через API (для партнёра)

Плюс: Мгновенная актуализация, меньше ручной работы.

Минус: Партнёр не поддерживает API; требуется доработка их системы (вне MVP).

2. Выгрузка в облачное хранилище (S3/Google Drive)

Плюс: Простота настройки, веб‑доступ.

Минус: Ниже безопасность (требуется дополнительная аутентификация).

Ручная отправка файла по email

3. Плюс: Не требует технических интеграций.

Минус: Высокий риск ошибок, задержки, отсутствие аудита.

4. Единая БД для банка и партнёра

Плюс: Общая актуальность данных.

Минус: Неприемлемый риск безопасности; партнёр не готов к доступу в корпоративную сеть.

**Недостатки, ограничения, риски**

**Недостатки выбранного решения:**

Задержка актуализации для партнёра (до 24 часов).

Зависимость от работоспособности SFTP‑сервера партнёра.

Ограниченный формат файла (нет интерактивности, как в веб‑интерфейсе).

**Ограничения:**

Партнёр не принимает API‑интеграции.

Объём файла ограничен 1 МБ (нельзя выгружать историю глубже 30 дней).

Синхронизация с кол‑центром банка только каждые 15 мин.

**Риски:**

Ошибка в файле (некорректные ставки) → жалобы клиентов.

Сбой SFTP → партнёр не получит файл → отсутствие консультаций.

Несовпадение ставок в системах → конфликт данных.

Перегрузка сервиса экспорта при росте числа партнёров.

Утечка файла со ставками (при слабой защите SFTP).

Отсутствие резервной копии файла у партнёра → потеря данных.
