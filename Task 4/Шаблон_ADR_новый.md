ADR: Передача ставок в кол‑центр (MVP)
1. Контекст

После запуска онлайн‑открытия депозитов ожидается рост звонков в кол‑центр. Пожилые клиенты нуждаются в консультациях по актуальным ставкам. Требуется:

обеспечить доступ к ставкам для штатных операторов кол‑центра;

наладить передачу ставок в партнёрский кол‑центр (внешняя система, приём только через файлы).

Текущие ограничения:

ставки хранятся в XLS‑файлах;

кол‑центр использует React.js/Java Spring Boot/PostgreSQL;

партнёрский кол‑центр принимает данные только в виде файлов (SFTP недоступен).

2. Требования

Функциональные:

сотрудники кол‑центра видят актуальные ставки в интерфейсе системы;

автоматическое формирование файла со ставками для партнёрского кол‑центра;

ежедневное обновление ставок в обеих системах;

история изменений ставок для аудита.

Нефункциональные:

доступность данных для кол‑центра — 99,9%;

задержка обновления ставок — не более 1 часа;

защита файла для партнёра (шифрование, контроль доступа);

логирование всех операций с ставками.

3. Рассматриваемые альтернативы

Ручная выгрузка XLS → отправка партнёру

Плюс: не требует разработки.

Минус: высокий риск ошибок, не соответствует требованию автоматизации.

Интеграция кол‑центра с XLS‑файлами

Плюс: простота.

Минус: ненадёжность, отсутствие аудита, невозможность передачи партнёру.

Централизованное хранилище ставок + автоматизированная выгрузка

Плюс: единые данные для всех систем, автоматизация, аудит.

Минус: требуется разработка нового сервиса.

Выбранное решение: вариант 3 (централизованное хранилище) как единственное, удовлетворяющее всем требованиям.

4. Решение

Диаграмма контекста (C4 Model)
Пользователь (Клиент) → [Кол-центр]  
Пользователь (Клиент) → [Партнёрский кол-центр]  

[Кол-центр] → [Сервис управления ставками]  
[Сервис управления ставками] → [Файл со ставками]  
[Партнёрский кол-центр] ← [Файл со ставками]  
[АБС] → [Сервис управления ставками] (синхронизация)  
Компоненты:

Кол‑центр — система на React.js/Spring Boot, отображает ставки.

Партнёрский кол‑центр — внешняя система, получает файл со ставками.

Сервис управления ставками — микросервис для хранения, обновления и выдачи ставок.

Файл со ставками — зашифрованный файл (например, CSV/XML) для партнёра.

АБС — источник актуальных ставок (заменяет XLS).

Диаграмма компонентов (детализация сервиса управления ставками)
Сервис управления ставками:

API для кол‑центра (REST);

модуль формирования файла для партнёра;

БД PostgreSQL (ставки, история изменений);

планировщик задач (ежедневное обновление);

модуль шифрования файла.

5. Последствия

Плюсы:

единые актуальные ставки для всех каналов;

автоматизация передачи данных партнёру;

аудит изменений ставок;

снижение нагрузки на сотрудников.

Минусы:

необходимость миграции данных из XLS в PostgreSQL;

дополнительные затраты на разработку сервиса.

Следующие шаги:

Разработка «Сервиса управления ставками».

Миграция ставок из XLS в PostgreSQL.

Интеграция сервиса с кол‑центром (API).

Настройка автоматического формирования и передачи файла партнёру.

Тестирование сценариев обновления ставок.

Список крупных задач по системам
1. АБС:

экспортировать актуальные ставки в сервис управления ставками (API/ETL);

обеспечить ежедневное обновление ставок в сервисе.

2. Сервис управления ставками:

разработать API для кол‑центра;

реализовать модуль формирования файла для партнёра;

настроить шифрование файла;

развернуть БД PostgreSQL;

интегрировать планировщик задач (например, Quartz).

3. Кол‑центр:

добавить раздел «Ставки по депозитам» в интерфейс;

реализовать вызов API сервиса ставок;

кэшировать данные для снижения нагрузки.

4. Партнёрский кол‑центр:

предоставить требования к формату файла (CSV/XML);

настроить приём и обработку файла.

RoadMap (6 месяцев — MVP, 12 месяцев — финальное решение)
Горизонт: 6 месяцев (MVP)

Месяц 1–2: Подготовка инфраструктуры

разработка сервиса управления ставками;

развёртывание PostgreSQL;

миграция ставок из XLS в БД.

Месяц 3: Интеграция с АБС

настройка экспорта ставок из АБС в сервис;

тестирование синхронизации данных.

Месяц 4: Интеграция с кол‑центром

разработка API для кол‑центра;

добавление раздела со ставками в интерфейс кол‑центра;

нагрузочное тестирование.

Месяц 5: Настройка передачи данных партнёру

реализация модуля формирования файла;

шифрование файла;

тестирование передачи данных.

Месяц 6: Запуск MVP

обучение операторов кол‑центра;

пилотный запуск (10% клиентов);

сбор обратной связи.

Горизонт: 12 месяцев (финальное решение)

Месяц 7–8: Оптимизация

внедрение кэширования ставок в кол‑центре;

настройка автоматического масштабирования сервиса управления ставками.

Месяц 9–10: Расширение функционала

добавление истории ставок в интерфейс кол‑центра;

интеграция с системой аналитики для прогнозирования нагрузки.

Месяц 11–12: Полная автоматизация

отказ от XLS-файлов (все ставки только в сервисе);

внедрение машинного обучения для динамического расчёта ставок;

масштабирование на все продукты банка (кредиты, накопительные счета).
